# 基于 FPGA 的视频稳像与移动目标检测系统项目计划书

**项目性质：**嵌入式视觉与 FPGA 软硬件协同开发    
**团队分工：**成员 A 负责 FPGA/HLS，成员 B 负责视觉算法与系统集成  
**版本：**讨论稿  

本计划基于前期讨论编制：拟采用 Zynq-7020 平台、Vivado/Vitis HLS 2020.2 和单目摄像头，实现相机运动条件下的视频稳像与多个移动目标检测。具体开发板型号、摄像头接口、运行系统和考核要求在第一阶段确认。

## 一、项目背景与目标

相机受到振动或发生移动时，静态背景也会在画面中产生运动。直接进行帧间差分，容易将背景误判为移动目标；同时，画面抖动会影响观察和后续检测。

本项目拟通过估计相机的全局运动，分别完成两项任务：

1. 平滑相机运动轨迹，补偿画面中的快速抖动。
2. 扣除相机运动造成的背景位移，提取独立运动的物体。

系统采用软硬件协同架构，将重复、计算量较大的图像处理交给 FPGA 可编程逻辑部分（PL），将运动模型估计、关键帧管理和目标跟踪交给 ARM 处理系统（PS）。

**项目最终交付一个能够实时接收视频、输出稳像画面，并标出移动目标位置的板卡演示系统。**

## 二、项目范围与预期指标

以下为设计目标，最终指标根据算法验证和板卡测试结果确定。

| 项目 | 基础目标 | 提升目标 |
|---|---|---|
| 视频输入 | 单路摄像头，640×480 | 条件允许时提高分辨率 |
| 处理速度 | 完整流程达到 20 帧/秒 | 达到 30 帧/秒 |
| 稳像能力 | 抑制小幅平移抖动 | 同时处理一定范围的画面旋转 |
| 持续相机运动 | 平滑跟随持续平移或摇摄 | 根据运动状态调整平滑强度 |
| 移动目标检测 | 在约定场景中检测一个或多个移动区域 | 改善遮挡、低对比度等场景的效果 |
| 目标跟踪 | 输出目标框及基本编号 | 减少交叉运动时的编号切换 |
| 硬件加速 | 完成块匹配模块并上板运行 | 根据性能瓶颈增加其他加速模块 |
| 运行稳定性 | 连续运行 10 分钟，无崩溃或持续卡死 | 延长稳定运行时间 |

本项目基础版本中的“检测”指发现**独立运动区域**，不等同于识别人、车等类别。语义识别列为可选扩展。

基础版本优先面向背景纹理较丰富、静态背景占画面较大比例、运动模糊较轻的场景。明显三维视差、大幅快速旋转和严重遮挡作为挑战场景记录，不承诺全部解决。

## 三、系统总体方案

系统先计算相邻帧之间的运动信息，再估计背景的全局运动模型。随后分为稳像和检测两条处理路径。

```text
摄像头／测试视频
        ↓
灰度化、可选下采样
        ↓
块匹配或稀疏光流
        ↓
匹配筛选 + 全局相机运动估计
        ├─────────────────────┐
        ↓                     ↓
累积并平滑相机轨迹       计算局部运动残差
        ↓                     ↓
图像变换与边缘裁剪       前景分割、连通域
        ↓                     ↓
稳像画面输出             目标框与目标跟踪
        └──────────┬──────────┘
                   ↓
          显示、性能统计与日志
```

**稳像与目标检测共享相机运动估计，但使用不同的补偿目标。**稳像保留平滑的相机运动；目标检测则尽量消除帧间背景运动，判断物体是否存在额外运动。

## 四、核心技术路线

### 4.1 软件算法基线

首先由成员 B 在电脑上使用 Python/OpenCV 实现完整流程，确认算法有效，再进行硬件迁移。

初期比较两种运动估计方法：

| 方案 | 主要用途 | 选择依据 |
|---|---|---|
| 稀疏光流＋RANSAC | 快速建立软件效果基线 | 开发方便，便于验证相机运动模型 |
| 块匹配＋RANSAC | 作为 FPGA 加速候选方案 | 运算结构规则，便于并行和流水线实现 |

使用同一组测试视频比较稳像效果、检测误差和耗时，确定第一版实现参数。

### 4.2 全局运动估计

采用 RANSAC 从匹配点中估计背景运动，减少错误匹配和移动物体的干扰。

实现顺序为：

1. 平移模型，跑通基本流程。
2. 相似变换模型，加入画面内旋转和统一缩放。
3. 仅在测试证明必要时，再评估更复杂的仿射或单应性模型。

### 4.3 稳像与关键帧管理

对估计得到的相机轨迹进行平滑，再计算当前画面需要施加的补偿变换。

重点处理：

- 区分短时抖动与持续相机运动；
- 限制补偿幅度，控制黑边和裁剪范围；
- 根据匹配质量决定是否更新参考帧；
- 更新参考帧时保持坐标变换连续；
- 在完整帧边界切换缓存和参数，避免帧内撕裂。

完整关键帧管理放在基础流程跑通后实现，优先保证逐帧处理正确。

### 4.4 移动目标检测与跟踪

根据全局模型预测背景点的位置，将实际匹配位置与预测位置之差作为运动残差：

```text
局部运动残差 = 实际匹配位置 − 全局模型预测位置
```

再结合图像差分完成：

1. 残差筛选与阈值分割；
2. 形态学处理；
3. 连通域提取；
4. 目标框生成；
5. 多帧确认与简单目标关联。

稠密光流作为提升方案，优先在低分辨率图像或候选区域使用。是否采用，以软件测试效果和板卡性能为依据。

### 4.5 FPGA 加速

成员 A 使用 HLS 实现块匹配计算模块，主要包括：

- 图像块读取与缓存；
- 候选位移搜索；
- 绝对差累加（SAD）；
- 最优候选选择；
- 匹配误差及置信度输出。

先完成 C 仿真，再完成综合和 C/RTL 协同仿真，最后导出 IP 接入板卡。

优化重点是缓存复用、流水线和适度并行，避免为了提高并行度导致资源不足或时序不满足。

## 五、成员分工与接口约定

| 工作内容 | 成员 A | 成员 B |
|---|---|---|
| 需求、测试场景、验收指标 | 共同制定 | 共同制定 |
| 电脑端算法基线 | 提供硬件实现约束 | 主要负责 |
| HLS 块匹配模块 | 主要负责 | 提供测试输入和参考输出 |
| Vivado 工程与 IP 集成 | 主要负责 | 配合 |
| PS 端控制与数据传输 | 配合接口调试 | 主要负责 |
| 稳像、检测及跟踪 | 提供加速结果 | 主要负责 |
| 上板测试、演示与文档 | 共同完成 | 共同完成 |

编码前建立统一接口文档，至少明确：

| 接口项目 | 约定内容 |
|---|---|
| 图像格式 | 宽高、灰度位宽、存储顺序、行跨度 |
| 坐标定义 | 原点位置、横纵轴方向 |
| 运动方向 | 明确表示“上一帧到当前帧”还是反方向 |
| 数据类型 | 位移的有符号位宽、整数或定点格式 |
| 块匹配结果 | 块位置、dx、dy、匹配误差、有效标志 |
| 帧管理 | 帧编号、缓存归属、数据完成标志 |
| 异常处理 | 丢帧、无有效匹配、模型估计失败时的行为 |

统一接口比统一编辑器更重要。两人可以使用不同编辑器，但必须共享数据格式、参数定义和测试样例。
